# Dependency and asset provenance

Pinned build/runtime downloads are listed in dependencies.lock.json. The
official sing-box archive checksum also matched the GitHub release asset
digest. Its extracted executable is byte-identical to the existing private
client's vendor copy. The Wintun archive checksum matches the upstream website
and its amd64 DLL matches the client's pinned runtime hash.

The font files and accompanying OFL notices were copied unchanged from the
existing client. Exact asset hashes are included in the publication inventory.
The three used service icons were replaced in this preparation with exact
paths from the pinned Simple Icons commit in icons-provenance.json. The original
upstream SVGs are retained in assets/upstream-icons, and their WPF paths are
generated by adding the F1 fill-rule prefix. Four unused historical icon entries
were omitted. Their license is CC0-1.0. Trademarks do not imply endorsement.
The custom R logo/icon originated in the private project. The owner must
confirm rights to publish that artwork under the proposed project license.

Both compressed geo resources were compared with the `rules` arrays in the
exact upstream JSON files. The parsed rules match. Version wrapper removal,
compact JSON serialization and GZip account for the byte difference between
the upstream files and these embedded resources. See geo-provenance.json.

## Go dependency audit

Read-GoBuildInfo.ps1 parses the executable's actual Go build-info section.
A raw binary strings search double-counts unrelated/embedded metadata, so it
must not be treated as the module inventory. The verified executable records
135 compiled Go modules with pinned versions and h1 checksums.

Get-GoModuleSources.ps1 downloads their exact Go module ZIPs from the public
module proxy and recomputes the Go directory hash from every ZIP entry.
The generated report records per-module license files and heuristic license
classifications. License terms themselves, including upstream extra notices,
are preserved in licenses/sing-box-dependencies.txt and in source archives.
All primary notices were classified, but that does not settle legal compatibility
or the native binary exception in Foundation policy.

Native prebuilt payloads are present in these module archives:
- github.com/sagernet/sing-tun: Wintun DLLs for multiple Windows architectures
- github.com/sagernet/cronet-go/lib/windows_amd64: libcronet.dll

Do not describe those archives as a source-only rebuild of every native byte.
The signed package eligibility question and remaining source review are tracked
in SIGNPATH-ELIGIBILITY.md. The current pipeline signs only R VPN-owned PE files.
